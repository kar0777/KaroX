# Native agent

`karox` accepts natural-language tasks after an API model is connected.
`karox agent run` is the non-interactive form. Both use `AgentKernel` and the
same repository-bound `CoreRuntime`, capability policy, session lease, audit,
verification and recovery used by bridges. The provider never receives direct
filesystem or unrestricted process access.

## Tools the agent is offered

Every Core tool the session's access profile permits is offered to the model, so
the native agent works with the same table the hosted bridge exposes to a web
client: `repo.read_file`, `repo.read_lines`, `repo.write_file`, `repo.edit_file`,
`repo.list_files`, `repo.search`, `checks.run`, `git.status`, `git.diff`,
`git.log` and `git.commit`.

A tool the origin may not call is not advertised, so a turn is not spent on a
guaranteed denial. Resolution still covers every Core tool: a model that names a
tool it was not offered reaches Core anyway, and the attempt is recorded in the
audit log as a policy denial rather than a generic "unknown tool" reply.

## Project instructions

Before the first request, KaroX reads the repository's own instructions from the
root of the checkout, least specific first:

1. `CLAUDE.md`
2. `AGENTS.md`
3. `KAROX.md`

All three are read when present, and each is named in the run's report, so
nothing is adopted invisibly. `CLAUDE.md` and `AGENTS.md` are other agents'
conventions, accepted because a user arriving with an existing file should not
have to retype it.

The text is **untrusted**. A checked-in file is written by whoever can commit to
the repository, which is not always the person running the agent, so it is
wrapped in a delimited block that says as much. It grants nothing: capabilities
come from the session access profile, and a tool result that contradicts an
instruction wins.

It is also **request-only**. Like Skill content, it is injected into the
provider-facing prompt and never written into the durable session history, so an
edited file cannot retroactively change what a past run was told and a handoff
document carries no third-party text.

Each file is capped at 32 KiB and the set at 64 KiB. A file cut short says so
inside the prompt rather than handing the model half a rule. A link, a directory,
or a path that resolves outside the repository is refused and reported.

Pass `--no-project-context` to skip all of it, including the environment stanza,
when reproducing a run that must not depend on either.

## Environment

The prompt states the repository path, the operating system, the path separator,
the Git branch, and the list of user-approved verification commands exactly as
approved, including the trailing `*` of any prefix rule. The allowlist is
deny-by-default, so naming it beats letting the model discover it by trial.

## Context

The transcript is resent on every step, so a single large read would otherwise be
paid for again on every later request. History is compacted against the routed
model's advertised input window — the smallest across a fallback chain, so a
fallback is never handed a history the primary model accepted. Oldest complete
turns are dropped first and replaced by a summary computed from the recorded tool
results, not generated by a model, so it costs no extra request and cannot invent
a change that never happened. Individual tool results are clipped in the outbound
view while the durable record keeps the full text.

Whole turns are dropped, never half of one: an assistant tool call whose result
is missing is rejected outright by every provider wire format.

## Finishing

A run that changed a file must produce a successful check plus Git status and
diff evidence before it is reported as verified; an unverified mutation is never
reported as success. A run that changed nothing is an answer rather than a failed
change, and reports `no_changes` after a single nudge instead of spending the
whole step budget being re-prompted.
