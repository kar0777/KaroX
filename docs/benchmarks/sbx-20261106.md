# KaroX v6 против OpenCode и DeepSeek Harness — песочница Linux, 05–06.11 (ветка `v6/win-20261105`)

Дата: 2026‑11‑05/06. Модель у всех `deepseek-ai/DeepSeek-V4.1-Flash-1017` через W&B Inference, максимальное усилие (KaroX `--effort-level ultra`, OpenCode `--variant max`, DSH `reasoningEffort: max`), контекст 1M. OpenCode 1.19.5, DeepSeek Harness 0.2.1‑rc.5. Машина: песочница 2 vCPU, 4 ГБ, без GPU (WebGL программный, SwiftShader). Цены W&B: вход $0.20/M, кэш $0.03/M, выход $0.65/M.

Задачи взяты из открытых популярных тестов, а не из арены: на них KaroX не настраивался, и в промптах и навыках KaroX нет ни одного слова из этих задач (это проверяют `test_instruction_neutrality` и `test_skill_scope`).

KaroX без проверочной команды не запускается, поэтому получил нейтральную команду: для страниц — свою общую проверку `python -m karox.web_check --render` и `--vision on`, для bowling — только проверку синтаксиса `python -m py_compile bowling.py` (она ничего не говорит о поведении). Условия: в a1 KaroX и OpenCode шли параллельно, DSH стартовал после KaroX (5 минут вместе с OpenCode, остальное время один); k1–k3 — KaroX один на машине. Против старой сборки KaroX у DSH были условия лучше, против k3 — почти такие же (первые 5 минут даже чуть хуже).

**Что нашли в k2.** Модель решила, что проверка `karox.web_check` «наверное ищет index.html», и тремя пробами скопировала свою страницу в `index.html`. После этого каждая проверка рендерила две одинаковые страницы (двойная цена), а закрывающий взгляд после исчерпания бюджета визуальных проверок судил `index.html` — он всегда первый в списке, — то есть копию, которую прогон своими инструментами не менял. Гейт правильно не засчитал такой «pass», и прогон с исправной страницей закончился «unverified». В папке осталась лишняя копия, а перед кодом — абзац текста, хотя задача требовала только код.

**Исправление (этот коммит).** Закрывающий взгляд судит страницу или SVG, которые изменил прогон (или страницу, которая загружает изменённый файл), а `index.html` — только если такой нет. Если одобрена `karox.web_check`, системный промпт говорит, что она сама находит каждую страницу `.html` и рисунок `.svg` в корне и копия не нужна. Закрывающий ход для ответа: если ответ должен состоять только из файла, поле `answer` остаётся пустым — KaroX сам вставляет файл и сам сообщает статус. Все три правила общие, без слов из задачи; на каждое есть тест (`tests/test_engine_kernel.py`), который на старом коде падает.

**Проверка исправления (k3).** Прогон закончился сам: VERIFIED, код выхода 0, 15.2 мин, $0.13, 28 шагов — быстрее и дешевле всех прошлых прогонов KaroX на этой задаче. Копий страницы нет (в папке только `aquarium-test.html`), итоговый ответ — ровно файл в одном блоке ```` ```html ````, без текста до или после. Визуальных проверок 4 вместо 7. Автоматическая проверка (та же, что в a1: headless Chromium, SwiftShader): ошибок консоли и упавших запросов нет, картинка меняется со временем (2.2% пикселей) и при повороте мышью (34%). На снимках — стеклянный аквариум с рамкой, рыбы‑клоуны, грунт из камней, растения, пузырьки, лампа и поверхность воды.

Честно: **на этой задаче DSH всё ещё быстрее** (11.2 мин против 15.2), но **в 2.7 раза дороже** ($0.36 против $0.13). Около 10 минут из 15 у KaroX — инструменты в программном рендере: 4 визуальные проверки по 70–77 с, 3 запуска `web_check --render` по ~40 с, браузерные пробы ~3.6 мин. На ПК с GPU эта часть должна стать намного дешевле, но аквариум на ПК я не замерял.

## Что изменено в KaroX (коммиты этой ветки)

- **Закрывающий взгляд судит страницу прогона.** После исчерпания бюджета визуальных проверок харнесс сам смотрит на последние байты — теперь на страницу или SVG, которые изменил прогон (или на страницу, которая загружает изменённый файл), а не всегда на `index.html`. Из‑за этого k2 закончился «unverified» с исправной страницей.
- Если одобрена `karox.web_check`, системный промпт говорит, что она сама находит каждую страницу `.html` и рисунок `.svg` в корне: копия в `index.html` не нужна.
- Закрывающий ход для ответа: если ответ должен состоять только из файла, `answer` остаётся пустым — KaroX сам вставляет файл и сам сообщает статус.
- `finish.answer_files`: если задача просит прислать содержимое файла в ответе, KaroX вставляет файл в итоговый ответ дословно, без повторной генерации; если файл нужно только сохранить, ответ остаётся коротким.
- Пустого итогового ответа больше нет: остановка по бюджету визуальных проверок оставляет один ход на ответ, а при его отсутствии печатается запасной текст.
- Браузер KaroX загружает библиотеки с публичных CDN для локальных страниц через кэширующий KaroX‑fetch — модель больше не копирует three.js в рабочую папку.
- Headless Chromium на Windows по умолчанию рисует WebGL видеокартой (на ПК с Radeon RX 570 кадр 16.7 мс вместо ~700 мс программного рендера); `KAROX_BROWSER_GPU=0/1` переключает вручную.
- Новый встроенный навык `svg-illustration` (рисунки, иллюстрации): структура объектов, правдоподобные контакты, один раунд полировки после «pass with notes». Чекер видов судит рисунки по тем же правилам.
- Потолок ответа чекера 3500 → 8000 токенов (на рисунках ответ обрезался и вердикта не было); обрезанный ответ так и называется.
- Полностраничный снимок документа без `<body>` (SVG) больше не висит 30 с.
- Чек‑лист требований, который модель заполняет при завершении, стал рекомендательным: он больше не переводит прогон в «unverified», если проверки и визуальный вердикт зелёные; держит прогон открытым только пункт, который модель сама назвала невыполненным.
- Новые файлы создаются с правами по umask, а не 0600.
- Неизвестное действие браузера получает подсказку «visual.check — отдельный инструмент» и ближайшее похожее действие.
- Навык `web-3d-scene` 1.7.0: кадрирование, рассыпанные поверхности, опоры — без слов из конкретных задач.

## Ограничения

- По 1–3 прогона на агента: это проверка направления, не статистика.
- Модель‑судья — та же модель, что у агентов; оценки только pelican.
- Без GPU 3D‑страницы рисуются программно (~3 с на кадр у тяжёлой сцены), поэтому визуальная самопроверка KaroX стоит ~1 минуту за взгляд. На машине с GPU эта цена почти исчезает.
