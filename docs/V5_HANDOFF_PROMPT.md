## 1. Что уже сделано (не переделывай)

Дерево закоммичено девятью логическими коммитами, `git status` чистый.
Последний коммит: `feat(bridge): enforce Smart Stop for hosted clients by

Реализовано и покрыто тестами:

* `src/karox/risk_engine.py` — единый RiskEngine и Smart Stop для любого
  источника агента. Четыре уровня, неизвестный вид действия = high, push /
  publish / payment / billing / account.delete = critical и всегда стоп.
  Движок нельзя сконструировать с автоодобрением выше medium.
* Контракт подтверждения: привязано к точному action digest, одноразовое, с

  ни в assessment, ни в события, ни в evidence. Дайджест намеренно игнорирует
  `source` и `summary`.
* `src/karox/risk_mapping.py` — перевод Core-команд в действия риска. Батч из
  30 правок считается как 30; `git push` внутри `process.run` распознаётся;
  `browser.command` оценивается по под-действию из payload.
* `src/karox/event_bus.py` — типизированный ограниченный поток событий с
  редакцией на входе, честным счётчиком `dropped`, изоляцией подписчиков,
  инкрементальным `since_seq` и performance spans по компонентам.
* `CoreRuntime._apply_smart_stop` — гейт стоит после проверок capability и
  **до** mutation lease, поэтому отклонённое действие не резервирует
  idempotency intent и не доходит до диска.
* `CoreToolBridge` по умолчанию включает Smart Stop. Мост **не даёт**
  хостед-агенту канала для подтверждения: он сам собирает `CoreCommand`, а
  токен в аргументах отбивается схемной валидацией. Не ломай это.
* `src/karox/process_identity.py` + реестр runtime v2 — сильная идентичность
  процесса (время создания из ОС, дайджесты executable/argv/владельца).
  Переиспользованный PID никогда не получает сигнал.
* `src/karox/launch_support.py` — capability-матрица лаунчера, машинные коды
  блокеров до запуска дочернего процесса.
* `scripts/check_wheel_contents.py` — гейт соответствия wheel исходникам.

Зелёное состояние на этом дереве: Ruff чисто, Mypy чисто (72 файла), полный

## 2. Ловушки среды. Прочитай, это сэкономит тебе часы

**CRLF ломает многострочные правки.** Часть файлов хранится в CRLF
(`src/karox/core.py`, `src/karox/tui_connections.py`), новые файлы в LF.
Guarded edit сравнивает байты, поэтому многострочный якорь с `\n` вернёт
`invalid_request`, хотя текст на экране идентичен. Решение: однострочные якоря
либо явные `\r\n` в якоре. Нормализация всего дерева нужна, но отдельным
осознанным коммитом вместе с `.gitattributes`.

**Длинный `tests.run` блокирует все записи.** `tests.run` помечен как
мутирующий, берёт эксклюзивный mutation lease и держит его весь прогон. Пока
идёт сплит, любая правка получает `SessionBusy`, который на проводе выглядит
как `denied`. Не запускай полный прогон параллельно с правками.

**4-way сплит не влезает в окно запроса.** Гоняй `split=8` для частей 1-3 и
`split=16` для остальных: 8-way часть `k` равна объединению 16-way частей `k` и
`k+8`, потому что файл `i` попадает в часть `i % n`. Так покрывается всё дерево
без таймаутов.

**Гейт счётчика тестов.** Любой новый тестовый файл ломает
`tests/test_release_gates.py`. Нужно обновить **пять** документов: `README.md`
(три места), `README_RU.md`, `docs/vNext/README.md` (три места),
`docs/IMPLEMENTATION_STATUS.md` (два места), `docs/RELEASE_CHECKLIST.md`.
Сначала узнай реальные числа из вывода упавшего гейта.

**`checks.run` работает только по allowlist.** Разрешены ровно три команды:
`python -m ruff check src tests scripts`, `python -m mypy src/karox`,
`python -m build --wheel`. Другое argv будет отклонено.

**Коммит через мост невозможен и это правильно.** `karox.git.commit` выключен
профилем, а `GIT_COMMIT` в политике даётся только `elevated`. Два независимых
замка. Не обходи их. Готовь блоки команд для Егора, как это сделано в
`docs/V5_COMMIT_PLAN.md`, и он выполнит их сам.

## 3. Правила безопасности

Без прямого разрешения Егора запрещено: commit, amend, push, force push, tag,
publish, release, `git reset`, `git clean`, `git stash`, rebase, destructive
checkout, массовое удаление untracked-файлов, изменение remote, переписывание
истории.

Перед правкой существующего файла: прочитай актуальное содержимое, проверь
окружающий код, применяй guarded edit, после правки перечитай участок и
прогони узкие тесты.

Запрещено: править ожидания теста вместо поведения, удалять падающий тест,
ставить `expectedFailure` вместо починки, снижать coverage gate, писать
документацию вместо кода, называть contract-тест live-тестом.

## 4. Оставшийся план, в порядке приоритета

### A. TUI читает поток событий, а не логи

Сейчас TUI рендерит текст логов. Подпиши его на `event_bus`. Session browser по
§25 скоупа: список сессий показывает задачу, агента, источник, provider/model,
workspace mode, статус, текущий шаг, число изменённых файлов, бюджет, время,
причину ожидания и одно первичное действие. Detail view: timeline, tool calls,
состояние браузера, diff, checkpoints, evidence, usage, cost, ошибки. Логи
открываются по запросу, а не занимают экран. Виртуализированные списки,
debounced refresh. Подтверждения Smart Stop должны появляться в TUI как
экран решения: сайт/цель, действие, последствия, безопасная альтернатива.
Именно TUI выдаёт `ledger.issue`, потому что подтверждение принадлежит
человеческому слою.

### B. Web-use UX, §15-21

Группа вкладок Chrome с названием `KaroX` и отличимым цветом, только агентские
вкладки, восстановление группы после reconnect. Убрать постоянную control-tab:
control plane живёт в service worker, authenticated loopback WebSocket, side
panel и popup. Видимый курсор агента: плавное движение, подпись, hover, click
pulse, fill/press индикаторы, `pointer-events: none`, исчезает при takeover,
без театральных задержек. Active tab identity: каждое действие привязано к
browser context ID, tab ID, navigation generation, ожидаемому origin и
correlation ID; перед click/fill/press проверять, что вкладка не сменилась.
Takeover сквозной: агент прекращает ввод, pending mutating actions отменяются,
курсор исчезает, UI показывает «Управляет пользователь», скриншоты
чувствительных зон приостанавливаются, после Resume агент продолжает в том же
контексте. Incremental snapshots вместо полного DOM. Retry только после
классификации причины, никогда вслепую.

### C. Parallel sessions, §24

Shared Read, Serialized Write через mutation queue и leases, Git Worktree,
Review Only. Обнаружение конфликтов по base digest, merge preview, запрет
tихого перетирания. Это не абстракция: 2026-08-02 два агента писали в одно
дерево без lease и едва не затёрли друг друга.

### D. Initiative Mode, §26

Off / Suggest / Safe Fix / Bounded Autonomous. Safe Fix только для объективных
дефектов после checkpoint. Субъективное (дизайн, шрифты, branding) — только
через diagnosis, предложение, preview и выбор пользователя. У каждого
проактивного прогона бюджеты времени, токенов, стоимости, шагов и файлов.

### E. Оставшийся frozen scope, §27

Plan/Act, checkpoints и undo, diff review с per-hunk accept/reject, file
mentions, image attachments, LSP diagnostics, themes, user commands, subagents,
skill marketplace, benchmarks.

### F. Двуязычие, §29

Централизованные каталоги сообщений. Запрещено: hardcoded русский рядом с
hardcoded английским, показ enum пользователю, разные функции в разных языках,
английская техническая ошибка внутри русского UI без remediation. Добавь
contract test на полноту каталогов.

### G. Сценарные тесты, §30

Семьдесят сквозных сценариев из скоупа. Часть уже покрыта (36, 37, 38, 39, 61
частично). Остальные нужно довести.

### H. Release engineering, §31-33

Coverage, installed-wheel smoke вне source tree, матрицы Windows/macOS/Linux и
Python 3.10/3.12/3.13, clean install, миграция с 4.x, откат прерванного
обновления, uninstall. Чего не можешь проверить на этой машине — готовь CI,
скрипты и шаблоны evidence, и не называй платформу пройденной без реального
прогона.
