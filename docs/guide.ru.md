# Руководство KaroX 6

[In English](guide.md)

KaroX — агент для программирования в терминале. Он читает, ищет и правит файлы, запускает
команды в вашем проекте и доводит задачу до проверенного результата. Одно ядро агента
работает в трёх режимах: интерактивный чат, запуск без интерфейса для скриптов и CI и
MCP-сервер для других AI-клиентов.

## Установка

Нужен Python 3.12 или новее; компиляторы не нужны.

```bash
uv tool install karox6            # или: pipx install karox6
uv tool install "karox6[tui]"     # редактирование строки и история ввода в чате
karox --version
```

Пока первого релиза нет на PyPI, ставьте из wheel:
`uv tool install "dist/karox6-<версия>-py3-none-any.whl[tui]"` (собрать: `uv build --wheel`).

### Обновление

`karox6 update` ставит самую свежую сборку ветки `karox6/main` в то окружение, из которого
запущен KaroX: клонирует ветку во временную папку, показывает, что изменится
(`6.0.0.dev34 -> 6.0.0.dev40` и заголовки коммитов между ними), собирает колесо, проверяет,
что оно запускается, и только потом заменяет установленное. Если что-то не так, прежний
KaroX остаётся рабочим. `karox6 update --check` только проверяет, `--force` переустанавливает.
`/update` в чате делает то же самое (после него перезапустите KaroX). В Windows запущенный
`karox6.exe` переименовывается, поэтому обновление работает и изнутри чата.

Чат проверяет новую версию не чаще раза в сутки, в фоне, и пишет об этом одной строкой
(`version X is available: /update`); сам ничего не ставит. `update_check = false` в
`config.toml` (или `KAROX_UPDATE_CHECK=0`) отключает проверку; `update_repo` /
`update_branch` задают другой источник.

Без работающего KaroX: `scripts/install_latest.ps1` (Windows) или `scripts/install_latest.sh`
создаёт venv, если его нет, и ставит или обновляет в нём KaroX; повторный запуск отвечает
«up to date». Папку задаёт `-Venv` / `--venv` (по умолчанию `~/karox6-venv`).

## Подключение модели

KaroX работает с любым OpenAI-совместимым API (`openai-chat`, по умолчанию), с OpenAI
Responses API (`openai-responses`), Anthropic (`anthropic`) и Gemini (`gemini`). Ключ
берётся из переменной окружения, *имя* которой вы указываете. Ключ нельзя передать
аргументом командной строки, а после чтения KaroX убирает переменную из своего окружения,
поэтому команды агента не могут её вывести.

```bash
export DEEPSEEK_API_KEY=...        # один раз, в профиле оболочки или хранилище секретов
karox chat -m deepseek-chat --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY
```

Настройки по умолчанию храните в `~/.karox6/config.toml` (или `$KAROX_HOME/config.toml`),
чтобы не повторять флаги. Флаги командной строки важнее переменных `KAROX_MODEL` /
`KAROX_PROVIDER` / `KAROX_BASE_URL`, а они важнее файла; `--profile ИМЯ` накладывает таблицу
`[profiles.ИМЯ]`:

```toml
model = "deepseek-chat"
base_url = "https://api.deepseek.com/v1"
api_key_env = "DEEPSEEK_API_KEY"   # имя переменной, а не сам ключ

[profiles.local]
model = "qwen3-coder"
base_url = "http://127.0.0.1:11434/v1"
api_key_env = ""
```

В чате то же делает `/setup`, без правки файлов: выберите провайдера, вставьте ключ
(скрытый ввод; ключ хранится зашифрованным для вашей учётной записи, у каждого провайдера
свой) и выберите модель из списка, который провайдер отдаёт для этого ключа. Каждый
настроенный так провайдер сохраняется таблицей `[profiles.ИМЯ]` и становится основным;
`/provider` показывает сохранённых, `/provider ИМЯ` переключает обратно без повторного ввода
адреса и ключа. `/model` (а также `/provider`, `/setup`) открывает
список выбора: стрелки — перемещение, ввод — фильтр, Enter — выбрать, Esc — отмена;
`/model ИМЯ|НОМЕР` переключает сразу, `/models [ТЕКСТ]` печатает модели провайдера.

Ещё полезно: `reasoning_effort`, `temperature`, `context_window`, `max_output_tokens`,
цены (`price_input`, `price_output`, `price_cached`, USD за 1M токенов; с ними видна
стоимость и работает `--max-cost`).

`context_window` — сколько принимает модель; `context_limit` (по умолчанию 400000) —
ваш рабочий бюджет. История сжимается у меньшего из двух, так что модель с окном 1M
работает в 400k, пока вы не поднимете лимит.

### Что KaroX знает о модели

`/status` и `/model` показывают, принимает ли модель картинки и каково её окно. Ответ
берётся из `models.json` в домашней папке KaroX (ваш файл главнее), затем из того, что
узнала сессия, затем из списка моделей провайдера (его читают `/model` и настройка: Mistral,
OpenRouter, Gemini и другие сообщают окно и приём картинок; в списке выбора это видно как
`1M · pictures`), затем из открытого каталога моделей [models.dev](https://models.dev)
(скачивается в фоне не чаще раза в день и хранится как `model-catalog.json`; запись этого
сервера для модели, иначе «принимает картинки», если так говорят почти все провайдеры с
этим именем), затем из встроенных фактов (Claude, GPT-4o и новее, Gemini, `-VL`-модели и
DeepSeek V4.1 Flash видят; gpt-oss и DeepSeek V3/R1 — нет). `model_catalog = false` в
`config.toml` (или `KAROX_MODEL_CATALOG=0`) отключает загрузку:

```json
{"models": {"zai-org/GLM-5.3-Flash": {"vision": false, "context_window": 200000},
            "my-local-*": {"vision": true}}}
```

Модель без зрения получает вместо картинки короткую пометку. Если провайдер отказался
принять картинки, KaroX записывает для этой модели `{"vision": false}` в `"learned"` и
повторяет запрос без них. Картинки от инструментов (скриншот, MCP-браузер, `read` файла
`.png`) получает любая модель, про которую не известно, что она их не принимает; отказ
запоминается так же.

## Чат

`karox chat` (или просто `karox` в терминале) открывает чат на весь экран: сверху лента
разговора; под ней строка о том, что делает текущий ход и сколько он идёт (`esc`
останавливает); в нижней кромке поля ввода — клавиши, нужные сейчас; в строке состояния —
модель, проект и ветка, заполнение контекста, стоимость (если заданы цены), время
последнего хода и режим разрешений. Ответ печатается по мере генерации уже размеченным
(заголовки, списки, `код`, блоки кода с подсветкой, выровненные таблицы), каждый вызов
инструмента — одна строка (под правкой видны изменённые строки, у команды — сколько строк
она вывела), а **Ctrl+O** раскрывает и сворачивает полный вывод всех вызовов. Перед
разрушительной командой агент спрашивает разрешения (`y` / `N` / `a` = разрешать до конца
сессии). С `--inline` чат остаётся в обычной прокрутке терминала.

Цвета подстраиваются под терминал: true color в Windows Terminal, VS Code, iTerm2, kitty и
WezTerm, 256 или 16 цветов в остальных, без цвета с `NO_COLOR` или `--no-color`. `theme` в
`config.toml` (или `--theme`, `KAROX_THEME`) выбирает `dark` или `light` (с подсвеченным
фоном строк диффа), `mid` (читается на любом фоне; по умолчанию, если терминал не сообщает
свой фон) или `ansi` (16 цветов самого терминала). В классическом окне консоли Windows
символы ограничены тем, что умеют его шрифты.

| Команда | Что делает |
|---|---|
| `/diff` | изменения в проекте: `git diff` и новые файлы |
| `/undo`, `/redo` | отменить последний ход (сообщения и изменённые им файлы) или вернуть его |
| `/fork` | продолжить в копии этого разговора; исходный остаётся как был |
| `/init [ФОКУС]` | модель пишет `AGENTS.md` для этого проекта |
| `/paste` (Alt+V) | приложить картинку из буфера обмена к следующему сообщению |
| `/mcp [СЕРВЕР]` | MCP-серверы: состояние, инструменты, как добавить |
| `/status`, `/cost` | сессия, модель, токены, контекст и стоимость |
| `/compact` | сжать разговор, чтобы освободить контекст |
| `/new`, `/clear` | новая сессия; очистить экран |
| `/sessions`, `/resume [ID\|last]` | список сохранённых сессий и продолжение |
| `/model [ИМЯ\|НОМЕР]`, `/models [ТЕКСТ]` | модель и список провайдера; сменить |
| `/provider [ИМЯ]`, `/setup`, `/key` | сохранённые провайдеры, настройка, ключ |
| `/approve ask\|allow\|deny` | как поступать с разрушительными командами |
| `/reasoning` | показать или скрыть рассуждения модели |
| `/export [ФАЙЛ]` | сохранить разговор в Markdown (по умолчанию `karox-<сессия>.md` в проекте) |
| `/effort [УРОВЕНЬ]` | насколько глубоко модель рассуждает: low, medium, high, xhigh, max или off (со следующего запроса) |
| `/update [check\|force]` | поставить свежий KaroX (см. «Обновление») |
| `/help`, `/quit` | справка; выход (или Ctrl+D) |

Esc или Ctrl+C останавливают текущий ход и сохраняют сессию. Enter отправляет; Alt+Enter,
Ctrl+J или `\` в конце строки — перенос. `@путь` прикладывает файл, `@shot.png` (или путь
перетащенной картинки) — картинку. Tab дополняет команды и пути, Ctrl+R ищет по истории
ввода, PgUp/PgDn и колесо мыши прокручивают ленту. Сообщение, отправленное во время работы
агента, ждёт своей очереди.

`/undo` записывает проект вокруг каждого хода в отдельное git-хранилище в
`<home>/snapshots`; ваш репозиторий, индекс и stash не трогаются, игнорируемые файлы не
записываются, а файл, который вы изменили после хода, остаётся как есть. `--no-undo`
отключает запись. `karox chat -c` продолжает последнюю сессию проекта, `--fork ID|last`
начинает новую с её копии.

## Запуск без интерфейса

```bash
karox run "почини падающий тест в tests/test_api.py"
echo "добавь аннотации типов в utils.py" | karox run -
karox run --json "..." > events.jsonl      # по одному JSON-событию в строке
karox run --resume last "теперь обнови changelog"
```

Коды выхода: `0` — готово, `1` — ошибка, `2` — неверные аргументы, `3` — сработал лимит,
`4` — агент остановлен, потому что повторялся, `130` — отменено.

С `--json` каждая строка — событие с полем `type`: `run_started`, `assistant_message`,
`tool_started`, `tool_finished`, `approval_requested`, `approval_resolved`, `usage`,
`retry`, `notice`, `compacted`, `error`, `run_finished` (`--stream` добавляет `text_delta`
и `reasoning_delta`). В `run_finished` — итоговый статус и причина.

Лимиты:

- `--max-steps N`: вызовов модели за ход (по умолчанию без ограничения).
- `--wrap-up-steps N`: после N шагов агента просят завершить текущую линию работы и
  проверить результат; ещё через 30 шагов — дать итоговый ответ (по умолчанию выключено).
- `--max-seconds`, `--max-cost` (нужны цены).

## Безопасность

Обычную инженерную работу KaroX делает сам: чтение, правки, тесты, сборки и локальные
команды git идут без вопросов. Под контролем небольшой набор разрушительных команд: рекурсивное удаление корня,
домашней папки, самого проекта или путей вне его, удаление `.git`, запись в блочные
устройства, форматирование и стирание дисков, `git push --force` и его варианты,
`DROP DATABASE` через клиенты баз данных. Проверка видит команды внутри `bash -c`,
`$(...)`, передачу в оболочку через pipe и аналоги в PowerShell.

`--approve-dangerous` выбирает, что делать с такими командами: `ask` (по умолчанию в
терминале), `deny` (по умолчанию без терминала) или `allow`.

Сессии сохраняются в JSON lines в `~/.karox6/sessions/<id>/session.jsonl`; в конце запуска
изменённые файлы копируются в `<сессия>/submissions` (`--no-snapshot` отключает).

## Внешние MCP-серверы как инструменты

Перечислите серверы в `~/.karox6/mcp.json` (или `--mcp-config ФАЙЛ`; `--no-mcp` — не
подключать):

```json
{
  "mcpServers": {
    "docs": {"command": "uvx", "args": ["some-mcp-server"], "env": {"LOG_LEVEL": "warn"}},
    "tracker": {"url": "https://example.com/mcp", "headers": {"X-Team": "core"},
                "bearer_token_env": "TRACKER_TOKEN", "timeout": 120}
  }
}
```

Токен берётся из переменной окружения, названной в `bearer_token_env`, а не из файла;
`${VAR}` (или `${env:VAR}`) в `env`, `args`, `headers` и `url` тоже берётся из окружения,
так что конфиги других MCP-клиентов работают как есть. Картинки, которые вернул сервер
(снимок браузера), сохраняются в файл, путь к нему есть в выводе инструмента.
Инструменты серверов видны агенту как `mcp__<сервер>__<инструмент>`. Инструменты, которые
сервер пометил как только читающие, выполняются параллельно с другими чтениями; длинный
вывод обрезается, а остаток сохраняется в файл, который агент может прочитать. `timeout`
(секунды, по умолчанию 600) ограничивает каждый вызов; вызов, который не уложился или был
прерван, отменяется и на сервере. Сервер, который не запустился, пропускается с
предупреждением, в котором приведён конец его stderr. Локальный сервер, упавший посреди
работы, перезапускается при следующем вызове (не больше 3 раз); если удалённый сервер забыл
сессию (перезапуск, истечение по простою), KaroX открывает новую и повторяет вызов один раз.

## Скиллы, свои слэш-команды и плагины

**Скилл** — папка с `SKILL.md` (формат Agent Skills, его читают Claude Code, Codex и
OpenCode): имя, описание того, когда его применять, и инструкции; файлы рядом (скрипты,
шаблоны) инструкции могут называть.

```markdown
---
name: release-notes
description: Write release notes from the git log. Use when asked for a changelog.
---
Write RELEASE_NOTES.md with one bullet per commit since the last tag ...
```

KaroX ищет их в `.karox/skills`, `.agents/skills` и `.claude/skills` проекта (и его
git-корня), в установленных плагинах, затем в `~/.karox6/skills`, `~/.agents/skills` и
`~/.claude/skills`; из одноимённых побеждает первый. В системный промпт попадают только
имена и описания (с ограничением размера); инструкции модель загружает инструментом
`skill`, когда задача подходит под описание. В чате `/skills [ТЕКСТ]` показывает список, а
`/ИМЯ [АРГУМЕНТЫ]` отправляет скилл вместе с вашим сообщением (`$ARGUMENTS` в тексте
заменяется аргументами). `karox6 skills` показывает, что найдено в текущей папке;
`skills = false` в `config.toml` (или `KAROX_SKILLS=0`) отключает скиллы.

**Свои слэш-команды** — промпты в файлах: `.karox/commands/ИМЯ.md` или
`.claude/commands/ИМЯ.md` в проекте, `~/.karox6/commands`, `~/.claude/commands`
(`group/name.md` становится `/group:name`). `/ИМЯ АРГУМЕНТЫ` отправляет текст файла; сама
модель их не загружает.

**Плагин** собирает скиллы, команды и MCP-серверы в одну папку (раскладка плагина Claude
Code подходит): `skills/`, `commands/`, `.mcp.json` или `mcp.json`, по желанию
`.claude-plugin/plugin.json`. `${CLAUDE_PLUGIN_ROOT}` (или `${KAROX_PLUGIN_ROOT}`) в команде,
аргументах, окружении или URL сервера — это папка плагина.

```bash
karox6 plugin install https://github.com/someone/their-plugin.git   # или локальная папка
karox6 plugin list
karox6 plugin disable their-plugin        # enable / remove
```

Плагины лежат в `~/.karox6/plugins`; ваш собственный `mcp.json` главнее одноимённого
сервера плагина. Установка ничего не запускает, но MCP-серверы плагина стартуют с каждым
чатом: ставьте плагины только из источников, которым доверяете.

## KaroX как MCP-сервер

`karox mcp` работает через stdio; `karox mcp --http 8765` — Streamable HTTP на
`127.0.0.1` с bearer-токеном. Клиент получает семь инструментов: `karox_run` (запустить
задачу; с `request_id` повтор не запустит её второй раз), `karox_status` (long-poll через
`wait_seconds`; короткий `log` — по строке на действие), `karox_approve`, `karox_cancel`,
`karox_diff`, `karox_files`, `karox_runs`. Задачи выполняются внутри `--root`, если не
указан `--any-cwd`.

Пример для клиента, который сам запускает серверы (Claude Desktop, Cursor и подобные):

```json
{"mcpServers": {"karox": {"command": "karox", "args": ["mcp", "--root", "/path/to/project"]}}}
```

Claude Code: `claude mcp add karox -- karox mcp --root /path/to/project`. Codex CLI, в
`~/.codex/config.toml`:

```toml
[mcp_servers.karox]
command = "karox"
args = ["mcp", "--root", "/path/to/project"]
```

Модель, провайдер и ключ берутся из настроек и окружения KaroX как обычно (или добавьте
`--model ...` в аргументы). Когда клиент уходит (закрывает соединение, останавливает сервер
через SIGTERM или просто убивает его на Windows), запущенные задачи отменяются, а их команды
останавливаются; запрос, который клиент отменил, остаётся без ответа, а сама задача идёт
дальше до `karox_cancel`.

KaroX из ChatGPT, Claude и других веб-клиентов (туннель Tailscale встроен): [chatgpt.ru.md](chatgpt.ru.md).

## Экспериментальные опции

Все выключены по умолчанию и останутся такими, пока не выиграют A/B-прогон на бенчмарке.

- `--copy-notes`: после `edit` KaroX ищет в проекте другие места (файлы того же типа; в
  git-репозитории — отслеживаемые), где ещё есть три подряд строки из заменённого кода, и
  добавляет до пяти таких мест к результату правки, каждое не больше одного раза за запуск.
  Так исправление в одной копии дублированного кода видно и в остальных. Поиск ограничен
  1,5 с и никогда не ломает правку.

- `--code-mode` добавляет `run_code`: агент пишет одну программу на Python, которая вызывает
  остальные инструменты как функции (`tools.bash(command=...)`, `tools.read(file_path=...)`,
  ...), и получает только то, что программа напечатала, — несколько вызовов инструментов
  обходятся одним шагом. Вложенные вызовы проходят те же проверки и подтверждения, что и
  прямые; ошибка вызова бросает `ToolError` и, если её не перехватить, роняет программу.
  Программы сохраняются в `<сессия>/code/`.
- `--subagents` добавляет `agent`: агент поручает исследование дочерней сессии с чистым
  контекстом (только чтение, поиск и shell) и получает обратно только её отчёт.

## Если что-то не так

- `--model is required`: укажите `-m` или `model` в `config.toml`.
- 429 и сбои провайдера (502/503/529) повторяются с паузами; это видно по событиям `retry`.
- В Windows `python3` часто лишь заглушка Microsoft Store; KaroX сообщает агенту, какой
  интерпретатор на самом деле работает.
- `karox debug rss` загружает рабочий стек и печатает занятую память.
