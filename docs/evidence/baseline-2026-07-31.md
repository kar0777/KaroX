## Open by design

```bash
python scripts/check_v5_release.py --strict
```

Fails, and should. Every remaining problem it reports is external evidence that
does not exist yet:

- seven conformance records at `pending` — ChatGPT Web, Claude Web, OpenAI
  Responses, Anthropic Messages, Gemini, generic OpenAI-compatible, external
  beta;
- four beta thresholds at 0 — unaided installation attempts (needs 5), completed
  primary scenarios (needs 3), completed without maintainer help (needs 2),
  second-task users (needs 2).

Nothing else. Every gate that can be satisfied by the repository itself is green,
which means the distance to a final `5.0.0` is measured in live runs and testers
rather than in code. The status fields stay `pending` until a dated real run
exists; `--strict` is the only thing standing between a pending record and a
`5.0.0` that would be claiming evidence it does not have.

## What it took to get here

The tree did not start green. Recorded because a baseline that hides its own
repairs is not a baseline:

- `988095a` — the accumulated 5.0 work, 108 files, committed with the fixes that
  made the gates pass rather than with the gates relaxed. Chief among them: a
  guarded child inherited the host console code page while its output was decoded
  as UTF-8 with `errors="ignore"`, so on this very machine a Cyrillic build
  failure was *deleted* and reached the agent as an empty string beside exit code
  1. Two tests asserted the opposite of the runtime's contract. `browser.read`
  and `browser.input` were pinned to pre-browser capability sets, so the product
  offered browser control under Build and then refused it with exit code 2.
- `dee041c` — three documents claimed a ChatGPT copy fix was still pending after
  it had shipped; both one-time migration helpers were applied, verified and
  deleted, which is what cleared `--strict` down to the live evidence above.

## Reproducing this

```bash
git checkout dee041ca01f712a350fe985eca0bec32cdd62bb3
python -m unittest discover -s tests -p "test_*.py"
python scripts/run_v5_preflight.py --static-only --keep-going --json
python -m ruff check src tests scripts
python -m mypy src/karox
python -m coverage run -m unittest discover -s tests -p "test_*.py"
python -m coverage combine && python -m coverage report
python scripts/check_v5_release.py --strict   # expected to fail; see above
```

Timings will differ. Counts, gate verdicts and the coverage percentage should
not; if they do on this commit, the difference is the environment and worth
chasing before trusting anything measured later.
