# KaroX из ChatGPT в браузере

`karox mcp --http` запускает KaroX как удалённый MCP-сервер (Streamable HTTP). ChatGPT
подключает его как пользовательский коннектор: вы описываете задачу в чате, ChatGPT
запускает KaroX на вашей машине, следит за ходом работы и показывает дифф.

## 1. Запустить сервер

```bash
export KAROX_MCP_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
karox mcp --http 8765 --root ~/projects --model МОДЕЛЬ [флаги провайдера]
```

Сервер слушает `127.0.0.1:8765`, его адрес — `http://127.0.0.1:8765/mcp/<токен>`.
Токен в пути — единственный ключ доступа, держите адрес в секрете. Без `KAROX_MCP_TOKEN`
сервер сам придумывает случайный токен и печатает полный адрес; заданный вами токен не
печатается. Токен и переменную с API-ключом сервер убирает из своего окружения, так что
команды агента их не прочитают. Запуски разрешены только внутри `--root` (снять
ограничение: `--any-cwd`).

Опасные команды (удаления, force push и т. п.) по умолчанию ждут подтверждения: ChatGPT
видит ожидающее подтверждение в `karox_status` и отвечает через `karox_approve`.
Подтверждайте только то, что прочитали сами: текст в репозитории может уговаривать
модель согласиться. `--approve-dangerous deny` — отказывать в них сразу.

## 2. Дать доступ по HTTPS

ChatGPT подключается из интернета, поэтому локальному порту нужен публичный HTTPS-адрес,
например через туннель:

```bash
ngrok http 8765            # или: cloudflared tunnel --url http://127.0.0.1:8765
```

Адрес коннектора: `https://<адрес-туннеля>/mcp/<токен>`. Любой, кто знает полный адрес,
может запускать задачи на вашей машине — закрывайте туннель после работы.

## 3. Добавить коннектор в ChatGPT

В настройках ChatGPT включите режим разработчика для коннекторов, создайте коннектор с
адресом из шага 2 без аутентификации (секрет — токен в адресе). Затем включите коннектор
в чате и попросите, например: «С помощью KaroX почини падающий тест в ~/projects/app и
покажи дифф».

## Инструменты

| Инструмент | Что делает |
|---|---|
| `karox_run` | запустить задачу в папке (или продолжить сессию); идемпотентен по `request_id` |
| `karox_status` | короткий лог (строка на действие), итоговый ответ, расход и ожидающие подтверждения; long-poll копит строки и отвечает раньше, только когда запуск закончился или ждёт подтверждения (`detail: full` — сырые события) |
| `karox_approve` | разрешить или запретить ожидающую опасную команду |
| `karox_cancel` | остановить запуск |
| `karox_diff` / `karox_files` | дифф рабочей папки / изменённые запуском файлы |
| `karox_runs` | запуски этого процесса сервера |
