# KaroX из ChatGPT, Claude и других веб-клиентов

`karox mcp --http` запускает KaroX как удалённый MCP-сервер (Streamable HTTP). ChatGPT,
Claude и любой клиент, принимающий адрес удалённого MCP-сервера, подключают его как
коннектор: вы описываете задачу в чате, ассистент запускает KaroX на вашей машине, следит
за ходом работы и показывает дифф. Чтобы работала сама модель чата, без второй модели и
API-ключа, см. [прямой режим](#прямой-режим-без-второй-модели).

## 1. Запустить сервер

```bash
karox mcp --http 8765 --root ~/projects --model МОДЕЛЬ [флаги провайдера]
```

Сервер слушает `127.0.0.1:8765`, его адрес — `http://127.0.0.1:8765/mcp/<токен>`.
Токен в пути — единственный ключ доступа, держите адрес в секрете. При первом запуске
сервер придумывает случайный токен, сохраняет его в `~/.karox6/mcp/http-token` (внутри
`--home`; читать файл можете только вы) и печатает полный адрес. Следующие запуски берут
тот же токен, так что однажды добавленный коннектор работает и после перезапуска: сессия
клиента продолжается, а запуски, начатые до перезапуска, сервер забывает, но их изменения
остаются на диске. `--new-token` делает новый токен (старый адрес перестаёт работать;
так стоит сделать, если адрес утёк). Чтобы задать токен самому, используйте
`KAROX_MCP_TOKEN`: такой токен не сохраняется и не печатается. Токен и переменную с
API-ключом сервер убирает из своего окружения, так что команды агента их не прочитают.
Запуски разрешены только внутри `--root` (снять ограничение: `--any-cwd`).

Опасные команды (удаления, force push и т. п.) по умолчанию ждут подтверждения: ChatGPT
видит ожидающее подтверждение в `karox_status` и отвечает через `karox_approve`.
Подтверждайте только то, что прочитали сами: текст в репозитории может уговаривать
модель согласиться. `--approve-dangerous deny` — отказывать в них сразу.

## 2. Дать доступ по HTTPS

Облачные ассистенты подключаются из интернета, поэтому локальному порту нужен публичный
HTTPS-адрес. С [Tailscale](https://tailscale.com/download) (вход выполнен, MagicDNS и
HTTPS-сертификаты включены) KaroX настраивает его сам:

```bash
karox mcp --http 8765 --root ~/projects --model МОДЕЛЬ --tunnel tailscale
```

Порт публикуется через Tailscale Funnel, KaroX печатает адрес коннектора
`https://<машина>.<tailnet>.ts.net/mcp/<токен>` (или с `:8443` / `:10000`, если порт 443
уже занят другой программой). Адрес не меняется между запусками, сертификат настоящий,
маршрут удаляется при остановке KaroX; маршруты других программ не трогаются. Если
Tailscale отвечает, что Funnel не включён, KaroX печатает ссылку в админку, которая его
включает. `--tunnel tailnet` использует Tailscale Serve: адрес доступен только устройствам
вашей сети tailnet (клиенту на телефоне или ноутбуке, но не облачным ассистентам).

Подойдёт и любой другой HTTPS-туннель:

```bash
ngrok http 8765            # или: cloudflared tunnel --url http://127.0.0.1:8765
```

Адрес коннектора: `https://<адрес-туннеля>/mcp/<токен>`. Любой, кто знает полный адрес,
может запускать задачи на вашей машине — останавливайте сервер или туннель после работы.

## 3. Добавить коннектор

Секрет — токен в адресе, поэтому везде выбирайте «без аутентификации».

- **ChatGPT**: Настройки > Приложения и коннекторы, включите режим разработчика, создайте
  коннектор с адресом из шага 2 и включите его в чате.
- **Claude** (claude.ai, приложения для компьютера и телефона): Настройки > Коннекторы >
  Добавить свой коннектор, вставьте адрес.
- **Другие клиенты** (Le Chat, Cursor, VS Code, MCP Inspector и т. д.): добавьте удалённый
  MCP-сервер (Streamable HTTP) с этим адресом или отправляйте
  `Authorization: Bearer <токен>` на `https://<адрес>/mcp`, если клиент просит заголовок.

Затем попросите, например: «С помощью KaroX почини падающий тест в ~/projects/app и
покажи дифф».

## Прямой режим: без второй модели

С `--direct` ассистент в чате (собственная модель ChatGPT, Claude и т. д.) сам делает
работу через инструменты KaroX: без `--model`, провайдера и API-ключа.

```bash
karox mcp --direct --http 8765 --root ~/projects/app --tunnel tailscale
```

Коннектор тогда предлагает вместо `karox_*` собственные инструменты агента: `read`,
`grep`, `glob`, `job_output`, `job_list` (помечены как только чтение) и `write`, `edit`,
`bash` (`pwsh` на Windows без Git Bash), `job_kill` (помечены как изменяющие, поэтому
ChatGPT спрашивает перед их вызовом). Относительные пути считаются от `--root`; пути вне
него запрещены, если не указан `--any-cwd`. Как и у агента KaroX, существующий файл нужно
прочитать, прежде чем `write` его заменит. Вызов возвращается не позже чем через 50 с:
более долгая команда продолжает работать как фоновая задача (её вывод — `job_output`);
задачи живут, пока работает сервер, и останавливаются вместе с ним.

Опасные команды (те же правила, что у агента) подчиняются `--approve-dangerous`: при `ask`
(по умолчанию) вызов отклоняется, а модели сказано спросить вас в чате; после вашего
согласия она повторяет вызов с `confirmed: true`. Это держится на честности модели,
поэтому `deny` отказывает в таких командах сразу (`allow` — выполняет их). Адрес, токен и
туннель работают как выше; без `--http` те же инструменты отдаются локальным клиентам по
stdio.

## Инструменты (режим агента)

| Инструмент | Что делает |
|---|---|
| `karox_run` | запустить задачу в папке (или продолжить сессию); идемпотентен по `request_id` |
| `karox_status` | короткий лог (строка на действие), итоговый ответ, расход и ожидающие подтверждения; long-poll копит строки и отвечает раньше, только когда запуск закончился или ждёт подтверждения (`detail: full` — сырые события) |
| `karox_approve` | разрешить или запретить ожидающую опасную команду |
| `karox_cancel` | остановить запуск |
| `karox_diff` / `karox_files` | дифф рабочей папки / изменённые запуском файлы |
| `karox_runs` | запуски этого процесса сервера |

Один ответ — не больше 100 000 символов: длинный список событий `karox_status` отдаёт
частями (следующая — с `since` = `next`), а слишком длинный дифф или итоговый ответ
обрезается с пометкой, сколько символов не вошло.
