# Консервативная политика RAM/диска — KaroX triad

- Windows C: резерв не менее **7 ГиБ**. Было 9,19 ГиБ, в завершающем замере 9,16 ГиБ; ext4.vhdx WSL физически размещается на системном диске даже если `df` показывает большой виртуальный размер.
- Windows D: резерв не менее **15 ГиБ**; завершающий замер 60,67 ГиБ.
- RAM: **один CLI за раз**, без параллельных subagent-копий 6 000+ файлов, без одновременных браузерных процессов. Linux agent+child tree ограничен до **1 GiB resident RSS** через watchdog в `audit/triad_linux.py`; при превышении, результат `INFRA_MEMORY_BUDGET_EXCEEDED` и не считается поражением качества.
- Уже установлены три официальных CLI в `~/.cache/karox-fair-linux-20261108`; повторная npm/uv установка НЕ нужна.
- Файлы бенчмарков и ledger — на D:, временные рабочие копии на Linux ext4 используются последовательно и удаляются по окончании каждого прогона.
- `audit/archive_evidence.py` сжимает ТОЛЬКО собственные редактированные логи, проверяя исходный SHA-256 поточно после распаковки. После проверки удаляется только исходный несжатый redacted log (gzip остаётся), не `result.json`, `changes.patch`, `visual_result.json`, кадры или пользовательские файлы. Происхождение доказательств сохраняется в `evidence_archives.json`.
- Дополнительные тяжёлые npm / браузеры / модели не запускать до нового измерения. Никакого удаления пользовательских файлов, чужих проектов, cache вне собственной WSL lab-папки.
