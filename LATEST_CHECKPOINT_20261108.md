## Security follow-up: проверка подмены checker, отдельный локальный gate

Штатный `core_process._karox_module_launch` исправленного wheel запущен с рабочим каталогом, содержащим злоумышленный `karox/web_check.py`, который при выполнении создал бы маркер `FORGED_CHECKER_EXECUTED`. Поддельный код **не выполнился**; `python -I` и привязка к действительно установленному KaroX загрузили оригинальный checker и вернули проверочный challenge. Результат `audit/SECURITY_SHADOW_E2E_20261108.json`, `correct=true`, exit 0. В рабочий репозиторий добавлен новый постоянный тест `tests/test_web_checker_origin.py::test_isolated_checker_execution_ignores_task_written_module`; полный его модуль + связанные `test_web_check.py` и `test_completion_gate.py`: **85 passed, 0 failed**, ruff PASS. `audit/SECURITY_SHADOW_REGRESSION_V2_20261108.json`. Это 1 новый тест сверх ранее зафиксированных 1 575, то есть совокупно 1 576 различных тестовых случаев с PASS=1 558, SKIP=18, FAIL=0 в разделённых проверках. Первоначальная попытка ruff дала 2 предупреждения о неиспользуемых импортах во вспомогательном скрипте, исправлены без изменения исполняемой логики; первый лог сохранён `audit/SECURITY_SHADOW_REGRESSION_20261108.json`. Новый security gate не выдает результата competitive triad; пользовательская установка не тронута.
