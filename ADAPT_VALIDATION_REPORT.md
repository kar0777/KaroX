## Что исправлено

### Выбор тестов
- Убрано молчаливое обрезание списка после 200 целей: при превышении лимита запускается весь набор.
- Исправлен разбор Git rename/copy и имён, буквально содержащих ` -> `.
- Согласовано обнаружение `*_test.py` в селекторе и исполнителе: Python-тесты больше не подменяются успешным `npm test` в смешанном проекте.
- Учтены изменения общей тестовой поддержки и исходники без надёжной привязки к тестам.
- Сохранена работа проектов, которым разрешены только явно утверждённые проверки и у которых нет тестового набора.
- Содержимое тестовых файлов читается один раз за выборку вместо повторного чтения для каждого изменённого исходника.

### Журнал событий и кэш
- Индекс SQLite ускоряет чтение редких типов событий без сканирования всей истории.
- Транзакция защищает выдачу номеров и идемпотентность между экземплярами хранилища.
- Чтение через то же соединение не показывает события, которые затем откатываются.
- Очистка старых событий работает при чередовании сессий и после повторного открытия хранилища.
- Отписка callback не пропускает следующий callback.
- Историческая оценка экономии не пересчитывается по новым тарифам; прежний контракт `None` при отсутствии текущих цен сохранён.

### Фоновые задачи и горячая перезагрузка
- Возврат рабочего дерева A→B→A не переиспользует старый job-id с его состоянием и маркером отмены.
- Убраны повторное чтение хвоста лога и повторные проверки идентичности в одном запросе.
- Логи записываются пакетами только там, где сохраняется точная семантика ограничения размера. Полные сохранённые байты, а не только последний хвост, сверены с исходной реализацией.
- Импортеры не получают наполовину выполненный модуль. Проверены реальные module locks, порядок зависимостей, rollback при исключениях и восстановление после появления зависимости.
- Неизменившаяся синтаксически ошибочная генерация не загружается повторно без необходимости; восстановимые ошибки импорта не кешируются навсегда.

### Состояние репозитория
- Хеширование и разбор проектных фактов используют один снимок байтов.
- Обновляются факты при создании/удалении инструкций и изменениях lockfile.
- Необъектный JSON кэша считается промахом, а не вызывает `AttributeError`.
- Повторные запросы метаданных для одного элемента заменены использованием уже полученного `lstat`.

## Измерения производительности

Три чередующихся парных запуска с реальными Git, SQLite, файловыми операциями и обработчиком секретов. Во всех девяти workloads проверено равенство семантического результата. Это синтетические компонентные измерения Linux, **не ускорение всего приложения или обещание таких же цифр на Windows**.

| Workload | Медиана отношения baseline/candidate |
|---|---:|
| Выбор тестов: 96 изменённых исходников × 1200 тестовых файлов | **3,49×** |
| Фильтрованное чтение журнала | **19,70×** |
| Захват коротких лог-строк с реальной маскировкой | **1,37×** |
| Захват с переполнением лимита лога, полный результат идентичен | **1,10×** |
| Карта проектных фактов | 1,05× |
| Чтение хвоста / progress-лог | около 1× |
| Запись события + чтение | 0,95×: небольшое замедление, сохранены новые гарантии транзакций |
| Контроль содержимого репозитория | Нестабильный результат, ускорение не заявляется |

**Неблагоприятный результат не скрыт:** в основном наборе контроль содержимого репозитория дал 0,546×, то есть кандидат был примерно в 1,83 раза медленнее. Последующие отдельные парные замеры после завершения тестовой нагрузки дали медиану 0,991× с одинаковыми результатами. Причина исходного расхождения не установлена. Сокращение количества запросов метаданных подтверждено, но устойчивое улучшение задержки для этого компонента не доказано.

Windows baseline: 4041 passed, 8 skipped, 342,64 с на 4 воркерах. Итог: 4172 passed, 8 skipped, 263,30 с на 6. Дополнительный параллелизм и большее количество тестов **не позволяют приписать разницу только оптимизации кода**.

## Честность проверок и оставшиеся ограничения

- Тесты не отключались, xfail не добавлялся, порог покрытия не снижался.
- Промежуточные ошибки реально исправлялись: несовместимая сериализация subtest, Windows CRLF в байтовой фикстуре, порядок закрытия SQLite относительно удаления временной директории, повторный вход в проверочный import-lock hook. Проверки гонок и проверка полного содержимого логов сохранены.
- Один диагностический запуск с ошибочным `--cov=karox` захватил временные копии пакета и был остановлен на стадии отчёта. Он **не используется** как финальное доказательство. Финальный запуск использует точный путь из CI: `--cov=src/karox`.
- Windows-пропуски: POSIX/Linux-специфичные проверки, создание symlink без необходимого разрешения, отсутствие bash, неоткрытый Traycer и неактивированный ручной long-job тест. Linux-пропуски в основном относятся к Windows desktop/console. Все причины сохранены в логах.
- macOS, реальные внешние клиентские сценарии и ручная desktop-сертификация в этом запуске не подтверждены.
- **Существовавшая ранее проблема безопасности остаётся:** принудительное разделение чрезвычайно длинной строки лога может разорвать распознаваемый секрет на части и пропустить его маскировку. Воспроизведено и на исходной, и на новой реализации; пакетная запись эту проблему не создаёт, но и не исправляет. До отдельного исправления не следует считать этот пакет безусловным разрешением на безопасный публичный релиз.

## Как воспроизвести

В отдельной копии исходной базы, после установки зависимостей и тестовых инструментов:

```text
git apply --check karox-v5-tests-performance.patch
git apply karox-v5-tests-performance.patch
python -m ruff check src tests scripts
python -m mypy src/karox
python scripts/run_v5_preflight.py --static-only --json
python -m pytest tests -n 4 --dist=loadfile --durations=40 -ra
python -m pytest tests -n 4 --dist=loadfile --cov=src/karox --cov-branch
python -m build --wheel
python scripts/check_wheel_contents.py
```

Для браузерных тестов установлен Chromium; в итоговых прогонах задано `KAROX_REQUIRE_BROWSER_TESTS=1`. Установленный console entry point должен находиться в `PATH`. Для компонентных Linux-бенчмарков нужны две отдельные копии, установленные зависимости и настроенный Git для временных fixture-коммитов:

```text
python benchmarks/reproduce.py --baseline BASE_CHECKOUT --candidate PATCHED_CHECKOUT --out NEW_OUTPUT_DIRECTORY
```

Workload-функции скрипта совпадают с выполненными измерениями. Переносимая упаковка проверена на синтаксис и запуск `--help`; полное повторное выполнение именно упаковочного wrapper не выдаётся за отдельный измеренный прогон.
