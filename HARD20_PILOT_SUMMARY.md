Причины, по которым **нельзя честно начинать платный пилот**:

1. **Нет гарантированного потолка $3/$30.** W&B сообщает, что месячный budget может применяться с задержкой и перерасход остаётся на клиенте. На машине пока нет проверенного единого metering gateway, через который гарантированно проходит *каждый* запрос всех 3 CLI, включая повторы, причины безопасности и визуальные LLM-проверки. Локальный арифметический watchdog — не средство контроля счета.
2. **MAX effort не верифицирован на уровне API.** Штатный Karo предлагает `--effort-level ultra`, установленный OpenCode V2 документирует модельный `#variant`, DSH позволяет задавать reasoningEffort в маршруте, однако фактические on-wire параметры DeepSeek/W&B ещё не подтверждены у всех трёх. Исторические комманды не проставляли max.
3. **Состав пока не заморожен.** Найдены 20 публичных кандидатов с официальными ID; только Three.js #35003 имеет собственные проверенные RED и GREEN. Для других SWE-bench Pro V2 HARD-51 есть публикация двухстороннего oracle/empty-patch gate, но индивидуальные RED/GREEN здесь не прогнаны. Остальные задач/среды/лицензии/верификаторы требуют отдельной проверки.
4. **Дисковое пространство под Docker ограничено.** C: ~9 ГиБ свободно, безопасный запас сверх 7 ГиБ только ~2 ГиБ. Уже существующий Docker кэш в WSL содержит ~7.83 ГБ образов и ~2.05 ГБ build cache; эти пользовательские объекты нельзя удалять без проверки происхождения. Каждая задача SWE-bench Pro декларирует 10 ГБ storage. Не загружать контейнеры без реального size preflight.

Положительные проверки без затрат: 20/20 smoke-тестов fail-closed accounting и протокольной целостности; Ruff PASS, compile PASS. Выдан `HARD20_PREFLIGHT_RESULT.json` со статусом `BLOCKED_NO_PAID_CALLS`; ротационный порядок трёх CLI заранее записан, но серия не активирована.
